# Windows 配置下发脚本设计说明

`script_builder.go` 的 `buildWindowsPushScript` 会整份生成目标机执行的 `.bat`，由 GSE
以 `system` 账号拉起。脚本本身只保留结构性的 `REM` 小标题，所有「为什么这么写」的背景
集中在本文，避免每次下发都把大段注释推到目标机上。

可读的完整示例（落地后的形态 + cmd 语法速查）见同目录
[`windows_push_script.example.bat`](windows_push_script.example.bat)。

改脚本前请先读本文对应章节：这里每一条约束都对应过一次线上故障，回退成「更自然的写法」
基本都会把故障带回来。

## 执行流程

```
0. 校验属主可解析为 SID
1. 解析目标目录与文件名
2. 创建目标目录（并给本次新建的层级授权）
3. 抢目录锁（临界区开始）
4. 备份原文件、按保留数清理旧备份
5. 写 base64 中转文件 -> certutil 解码 -> 按期望长度校验（不通过整份重写）
6. move 原子替换目标文件
7. 设置属主与权限
8. 输出 dir / MD5，释放锁退出
```

失败标记（脚本用 `echo` 打出，可直接在 GSE 任务输出里检索）：

| 标记 | 含义 |
|------|------|
| `OWNER_NOT_FOUND` | 属主账号无法解析成 SID |
| `MKDIR_FAILED` | 目标目录创建失败 |
| `ACL_FAILED` | `icacls` 设置属主或权限失败 |
| `LOCK_TIMEOUT` | 等待目录锁超过 60 秒 |
| `WRITE_TMP_FAILED` | base64 中转文件创建不出来 |
| `DECODE_FAILED` | `certutil -decode` 失败 |
| `WRITE_TMP_TRUNCATED` | 解码产物长度与期望不符，重试后仍不符 |
| `MOVE_FAILED` | `move` 替换目标文件失败（重试 10 次后） |

## 各处约束与原因

### 0. 属主必须先解析成 SID 才动盘

写盘之前先用 `NTAccount.Translate` 确认属主能解析（与 `icacls` 同一套
`LookupAccountName`）。同目录并发时多个任务会一起在这里失败，此时既不会 `mkdir`，
已存在的配置也不会被改属主。

### 授权用内置管理员组的 SID，不动态查用户所属组

部分账号（域账号、服务账号等）通过 WMI 查不到关联组，查询本身还容易受 WMI 服务状态
影响。按 SID 而非组名授权：组名随区域设置本地化（德语是 `Administratoren`）且可被
重命名，按名字解析不到时 `icacls` 会失败并导致下发任务报错；`S-1-5-32-544` 在任何
机器上都稳定存在。`icacls` 里的 `*` 前缀表示按 SID 解析。

### 2. 目录创建失败必须当场终止

临时文件也落在目标目录下，目录建不出来就必须立刻失败，否则错误会一路滑到后面的
`move`，报成含义完全不同的「找不到文件」。

收集待创建层级的循环里，上溯到驱动器根之后父目录不再变化，用
`if "!DIR_PARENT!"=="!DIR_CUR!"` 收尾，避免路径异常时死循环。

属主只作用于本次 `mkdir` 新建出来的层级：`mkdir` 是递归的，建完就分不清哪几层是新建
的，因此必须在 `mkdir` 之前把待创建层级记下来。

### 3. 目录锁：串行化同一目标文件的并发下发

Windows 的 `move` 替换已存在的目标要求以 DELETE 访问打开它，而备份 `copy`、`icacls`、
`certutil -hashfile` 打开目标文件时都不带 `FILE_SHARE_DELETE`。任何一方在窗口期持有
句柄，另一方的 `move` 就会拿到 Access is denied（`MOVE_FAILED`）。

锁按目标文件名区分并落在目标同目录，不同文件的并发下发互不阻塞；用 `md` 的原子性抢锁，
抢不到就自旋等待。持锁后的所有失败路径统一收敛到 `:fail`，先 `rmdir` 释放锁再以非零码
退出，不能直接 `exit /b`。

### 睡眠一律用 `ping`，不能用 `timeout`

`timeout` 在 stdin 被重定向的 GSE 环境下会直接报
`Input redirection is not supported`。`ping 127.0.0.1 -n 2 >nul` 借两次探测之间的默认
间隔实现约 1 秒睡眠。

### 临时文件名的唯一后缀由服务端生成

不能用 cmd 的 `%RANDOM%`：它在进程启动时以系统时钟播种，被 GSE 同时拉起的多个脚本会
取到完全相同的序列。同一台主机上下发同名配置很常见（若干个 .NET 服务各有一份
`Web.config`，只是目录不同），撞名后它们会互相覆盖中转文件、互相删除解码产物，表现为
`certutil` 报 ERROR_FILE_EXISTS、`move` 找不到文件，甚至静默写入别人的内容。后缀改由
服务端的 `newTempToken` 生成。

备份文件名的时间戳精确到毫秒，同样是为了防止同秒并发覆盖。

### 5. base64 分块写入、中转文件位置、写盘后自校验

**为什么分块**：cmd.exe 解析批处理时单行有约 8191 字符上限，超出部分被静默丢弃。整份
base64 写在一行里，配置超过 6 KB 左右就会被截断。现在按 `windowsB64ChunkSize`（1024，
必须是 4 的倍数，否则会切在 base64 四字符组中间）切成多行追加。

**为什么重定向写在 `echo` 前面**：`echo x > f` 会把 `>` 前的那个空格一起写进文件；而
base64 字母表含数字，`echo ...1>f` 里的末位数字会被 cmd 当作重定向句柄吃掉，内容静默
少一个字符。base64 字母表（`A-Za-z0-9+/=`）不含 cmd 元字符，无需转义。

**为什么中转文件放 `%~dp0`（脚本自身所在目录，即 GSE 的脚本落地目录）**：目标常常是
IIS 应用根，ASP.NET 的 FileChangesMonitor 与杀软、索引都会对该目录里新出现的文件做
open，而中转文件要被连续追加十几段，任何一次 open 失败都会静默少写一段。脚本自己就在
那个目录里、且已明文含同一份 base64，换过去不引入新的暴露面，也不用建目录。中转文件
只被 `certutil` 读一次随后删除，不参与 `move`，因此不要求与目标同卷。

中转文件连创建都失败（脚本目录不可写等）时退回目标同目录，即改动前的行为；写残的情况
文件是建出来了的，仍留在脚本目录里重写。

**为什么解码产物仍留在目标同目录**：`move` 只有同卷内才是原子 rename，跨卷会退化成
「拷贝 + 删除」，业务进程有机会读到只写了一半的配置；而且同卷 `move` 不会重新继承目标
目录的 ACL，换个目录创建会把那个目录的继承权限带到配置文件上。

**为什么必须按期望长度自校验**：每行 `>> echo` 的重定向失败既不中断脚本，也不体现在
最终退出码上（杀软扫描、文件系统过滤器、句柄占用、磁盘空间不足都可能让后面若干行静默
写不进去）。每段长度又都是 4 的倍数，残缺的 base64 依然是合法输入，`certutil` 会把
「前 N 段」照样解码成一个语法上看起来正常的文件，`move` 与退出码全部正常，任务报成功，
只有人工比对配置才能发现。因此拿服务端算好的 `EXPECTED_SIZE` 比对解码产物字节数
（用 `for` 的 `~z` 修饰符取）。

不能比对 `.b64` 的长度：它还含每行的换行符；只有解码产物的长度与服务端渲染出的内容
一一对应。

**校验必须在 `move` 之前**：放到 `move` 之后即使报错，残缺配置也已经覆盖上去了。现在
校验不通过就整份重写，最多 3 次，仍不通过带非零码退出，目标文件保持原内容不变。

### 6. `move` 重试

业务进程偶发的轻微句柄占用会让 `move` 失败，重试约 10 次、每次间隔 1 秒。

### `certutil -decode` 必须带 `-f`

不带 `-f` 时 `certutil` 拒绝覆盖已存在的输出文件，会报 `0x80070050`
（ERROR_FILE_EXISTS）。

### 本次改动的故障背景

剑灵怀旧服 `D:\bnsserver\ManagementWeb\web.config`，期望 10052 字节，间歇落盘成 6912
或 2304 字节，恰好等于前 9 段、前 3 段 base64 解码后的长度，而 GSE / BSCP 仍报
`script execution success`。

已排除：服务端渲染内容缺失、bat 里 echo 段数或 payload 残缺（失败与成功三次脚本解码
结果 MD5 完全相同）、同一目标文件双写。

失败时段的共同特征是同机高并发下发（同一秒约 25 个 bat），且同批 30 多个目标里只有 IIS
应用根下的 `web.config` 写残——这是把中转文件挪出目标目录的直接依据。

## 开发注意

- 脚本是 `fmt.Sprintf` 模板，bat 里的 `%` 要写成 `%%`，`for` 变量 `%%i` 要写成 `%%%%i`。
- GSE 以 UTF-8 + CRLF 落地脚本；中文只出现在 `REM` 与 `echo` 里，UTF-8 多字节序列不含
  cmd 元字符，在 GBK 代码页下最多显示乱码，不影响执行。
- 脚本文本的断言集中在 `script_builder_test.go`，Windows 侧只做文本断言（CI 无 Windows
  环境），改完仍需在真机上跑一次正常下发与一次人为写残的用例。
