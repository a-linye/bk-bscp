## 需求背景

### 业务背景

**本子需求解决的具体问题**：bscp 的 CMDB 客户端类型定义中已含 `Priority int` 字段（`internal/components/bkcmdb/type.go`），但 CMDB 同步链路在构建进程数据时未读取该字段，导致业务在 CMDB 上配置的启动优先级在 bscp 侧完全不可见、不可用。没有这份数据，后续任何优先级编排都无从谈起。

**在整体需求中的定位**：本子需求是父需求的数据与契约基线（Wave 1）。它交付三件事：

1. 让 CMDB 的 `priority` 在 bscp 侧落库并可查询——为 Wave 2 的编排引擎提供数据输入
2. 定义**批次编排数据契约**（批次与实例任务的归属关系、待执行任务的状态语义、批次终态回调钩子）——使 Wave 2/Wave 3 的编排引擎、失败级联、方向适配三个子需求可照契约并行开发，而不必等待彼此的实现
3. 在任务详情中展示进程优先级——本身即可独立演示，用户可立即验证"CMDB 配置的优先级已被 bscp 正确读取"

选择「数据同步 + 详情展示」合并为一个子需求，而非拆成两个碎需求，原因是二者构成一条最短的端到端可演示链路（CMDB 配置 → 同步落库 → 界面可见），符合 MVP 骨架优先原则；单独拆出前端展示会形成 6 人时的碎需求。

## 功能需求

### 核心功能点

| 功能编号 | 功能描述 | 优先级 | 涉及角色 | 备注 |
|---------|---------|--------|---------|------|
| F-001 | CMDB 同步链路保留并持久化进程启动优先级 `priority`，bscp 侧只读 | P0 | 业务运维 | 必须 |
| F-002 | 定义批次编排数据契约（批次-任务归属、待执行任务状态语义、批次终态回调钩子） | P0 | 研发 | 必须 |
| F-003 | 任务详情接口返回进程优先级，前端任务详情表格新增「进程优先级」列 | P1 | 业务运维 | 必须 |

### 详细功能描述

#### [F-001] CMDB 优先级同步与持久化

- **输入**：CMDB 进程属性中的 `priority`（启动优先级），随现有 CMDB 定时同步（默认 30 分钟一轮、每轮 10 个业务、仅 master 节点执行）或用户在 UI 手动触发同步获取
- **处理逻辑**：
  1. 现有 CMDB 同步链路解析进程属性时，保留 `priority` 值（当前该字段被读取后丢弃）
  2. 将 `priority` 与进程记录一并持久化到 bscp 侧，使其可按进程查询
  3. `priority` 缺失、为空或为 `null` 时，按 **0** 处理
- **输出**：bscp 侧每个进程具备可查询的启动优先级
- **边界条件**：
  - `priority` 为整型，可为负数（负数视为比 0 更早启动），不限制上下界
  - CMDB 上修改 `priority` 后，最长需等待一轮定时同步（默认 30 分钟）生效；用户可手动触发同步立即生效
  - bscp 侧不提供优先级编辑入口，唯一数据源为 CMDB
- **异常处理**：
  - CMDB 同步失败 → 沿用上一次同步值，不因缺少 priority 阻断进程操作
  - CMDB 返回非整型 priority → 按 0 处理，并记录日志

#### [F-002] 批次编排数据契约定义

- **输入**：父需求确定的编排语义（同优先级一批并行、跨优先级串行、非全成功即阻断后续）
- **处理逻辑**：
  1. 定义批次与实例任务的归属关系：一次操作请求产生一个任务批次，批次内按优先级划分为多个有序波次，每个实例任务归属唯一波次
  2. 定义**待执行任务的状态语义**：一次操作请求的全部实例任务在批次创建时即落库（而非下发时才创建），未下发的任务处于「待执行」语义，使后续优先级的任务在被级联阻断时有可更新的记录
  3. 定义批次终态回调钩子：单个波次全部实例任务到达终态时触发的回调契约，供编排引擎（下发下一波）与失败级联（阻断后续）分别挂载
  4. 提供基于契约的可校验产物：数据结构定义 + 状态流转说明，使 Wave 2/Wave 3 子需求可照契约并行开发
- **输出**：批次编排数据契约（唯一真相源），Wave 2 及以后子需求均引用本契约，不重复定义
- **边界条件**：
  - 契约在 Wave 1 完成后进入冻结期，Wave 2 开发期间原则上不修改；必须修改时评估全部引用方影响面
  - 契约只定义数据结构与状态语义，不包含调度算法实现（调度实现属 Wave 2）
- **异常处理**：
  - 契约与现有任务批次机制冲突 → 以向后兼容为准，新增字段而非修改既有字段语义

#### [F-003] 任务详情展示进程优先级

- **输入**：用户查看任务批次详情
- **处理逻辑**：
  1. 任务详情查询接口在实例任务项中返回对应进程的 `priority`
  2. 前端在任务详情的实例维度表格中新增「进程优先级」列
- **输出**：任务详情表格可见每行实例的优先级
- **边界条件**：
  - 优先级取值为 0 时显示 `0`（不显示为空）
  - 优先级缺失/不可取得时显示 `--`
  - 保持现有扁平实例列表形态，不做按优先级分组折叠或分阶段进度条
- **异常处理**：
  - 优先级字段取不到 → 显示 `--`，不影响表格其余内容渲染

## 接口契约定义

本子需求承担 Wave 1 契约职责，契约内容如下；Wave 2 及以后子需求引用本节，不重复定义。

### 接口签名

| 接口 | 方法/路由 | 入参 | 出参 | 调用方 → 提供方 |
|------|----------|------|------|----------------|
| 进程操作 | `POST /api/v1/config/biz/{biz_id}/process/operate` | 保持现状，**不新增字段** | 保持现状（批次 ID） | UI → config-server → data-service |
| 任务批次详情 | `POST /api/v1/config/biz/{biz_id}/task_batch/{batch_id}/detail` | 保持现状 | 实例任务项**新增** `priority` 字段 | UI → config-server → data-service |
| 批次波次终态回调 | 内部回调契约 | 批次 ID、波次标识、该波次实例任务终态集合 | 是否继续下发下一波次 | 任务框架回调 → 编排引擎 / 失败级联 |

### 数据结构

| 名称 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 进程 | `priority` | int | 启动优先级，来源 CMDB，bscp 只读，缺省 0，允许负数，无上下界 |
| 任务批次波次 | 批次标识 + 波次序号 + 波次优先级值 | int | 一次操作请求内按优先级划分的有序波次；波次序号自 1 递增，与执行顺序一致 |
| 实例任务 | 所属波次标识 | int | 每个实例任务归属唯一波次，用于批次门控与级联阻断定位 |
| 实例任务 | 待执行状态语义 | 枚举 | 批次创建时全量落库；未下发的任务为「待执行」，可被级联阻断更新为失败 |
| 任务详情项 | `priority` | int | 该实例对应进程的优先级；不可取得时前端显示 `--` |

> 落库形态（独立列 / 现有 JSON 结构内字段 / 新增关联表）属技术方案范畴，由开发阶段决定，但须满足本契约的可查询与可更新语义。

### 协议与错误码

| 错误码/状态 | 语义 | 触发场景 |
|------------|------|---------|
| 沿用现有鉴权错误码 | 无进程操作权限 | 用户无权限调用进程操作接口，与改造前一致 |
| 沿用现有同步错误处理 | CMDB 同步失败 | 保留上次同步的 priority 值，不新增对外错误码 |

> 优先级阻断专用失败原因文案由《批次失败级联阻断》子需求定义，本契约不预设。

## 非功能需求

### 性能需求

- **同步开销**：新增 priority 字段的同步不改变现有 CMDB 同步的批次规模与频率（默认 30 分钟一轮、每轮 10 个业务）
  - 测量场景：单轮同步 10 个业务
  - 测量方式：对比改造前后单轮同步耗时，增幅 ≤ 5%（同环境连续 3 次取均值）
- **详情查询开销**：任务详情接口新增 priority 字段后，单次查询响应时间增幅 ≤ 5%
  - 测量场景：单批次 2000 个实例任务的详情查询
  - 测量方式：同环境连续 3 次取均值对比

### 安全需求

- **权限控制**：沿用现有进程操作与任务详情查询的 IAM 鉴权，**不新增**权限点，不放宽任何现有校验
  - 测量方式：无对应权限的用户调用接口，返回鉴权失败，错误码与改造前一致
- **数据保护**：`priority` 为非敏感数据，无加密/脱敏要求
- **合规要求**：无新增

### 可用性与稳定性

- **容错能力**：CMDB 同步不可用时使用上一次同步的 priority 值；优先级信息缺失时按 0 处理，不返回错误
  - 测量方式：断开 CMDB 后执行进程操作，操作正常下发，不因缺少 priority 报错
- **数据兼容**：改造前已存在的历史任务批次记录无优先级信息，任务详情中该列显示 `--`

## 验收标准

### 功能验收

**F-001 优先级同步与持久化**

- [ ] **AC-001**（正例）Given CMDB 上某进程 `priority` 配置为 3，When 触发 CMDB 同步完成后查询该进程，Then bscp 侧该进程的优先级为 3，且任务详情中该进程实例的「进程优先级」列显示 `3`
- [ ] **AC-002**（反例）Given CMDB 上某进程 `priority` 为空或字段缺失，When 触发 CMDB 同步完成后对其执行 start，Then 该进程按优先级 0 参与后续编排，任务详情「进程优先级」列显示 `0`，且操作不报错
- [ ] **AC-003**（反例）Given bscp 侧无任何进程优先级编辑入口，When 用户在进程管理页查找修改优先级的操作，Then 页面不提供该入口；用户在 CMDB 修改后经同步生效
- [ ] **AC-004**（反例/边界）Given CMDB 返回的 priority 为非整型或负数 -1，When 同步完成，Then 非整型按 0 处理并记录日志；-1 被原样落库且参与排序时排在 0 之前
- [ ] **AC-005**（反例）Given CMDB 接口不可用，When 定时同步执行，Then 进程记录保留上一次同步的 priority 值，进程操作可正常发起，不因缺少 priority 被阻断

**F-002 批次编排数据契约**

- [ ] **AC-006**（正例）Given 一次操作请求命中 priority=1 的 5 个实例与 priority=2 的 5 个实例，When 批次创建完成，Then 全部 10 个实例任务记录均已落库，其中 priority=2 的 5 个处于「待执行」语义，波次归属为波次 2
- [ ] **AC-007**（反例）Given 批次创建后服务重启，When 查询该批次，Then 波次划分与各实例任务的波次归属信息完整保留，不因重启丢失
- [ ] **AC-008**（正例）Given 契约已发布，When Wave 2/Wave 3 子需求文档引用批次编排契约，Then 三者引用的数据结构与状态语义完全一致，无重复定义或冲突表述

**F-003 任务详情展示**

- [ ] **AC-009**（正例）Given 一个含多优先级实例的任务批次，When 用户打开任务详情页，Then 实例维度表格中存在「进程优先级」列并显示各实例优先级值；表格仍为扁平列表，不出现按优先级分组折叠或分阶段进度条
- [ ] **AC-010**（反例）Given 改造前产生的历史任务批次（无优先级信息），When 用户打开其任务详情，Then「进程优先级」列显示 `--`，页面其余内容正常渲染无报错
- [ ] **AC-011**（正例/边界）Given 某实例对应进程的优先级为 0，When 用户查看任务详情，Then 该行「进程优先级」列显示 `0` 而非空白或 `--`
