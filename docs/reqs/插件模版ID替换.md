## 需求背景

### 业务背景

进程配置管理插件在标准运维（bk-sops）流程中提供进程操作与配置操作能力。其中三个配置类操作
——生成配置、下发配置、检查配置——允许用户圈定「本次操作哪些配置模版」，当前圈定方式是
**填写配置模版名称**。

配置模版名称在业务内唯一，但**可以被删除后用同名重建**。重建出来的是一条全新的模版记录，
内容、绑定的进程范围、文件路径都可能与原来完全不同。此时按名称圈定的存量流程不会有任何提示，
会静默作用到这个「同名但不同」的模版上，导致生成或下发了非预期的配置内容。配置下发直接影响
线上进程读取的配置文件，误下发的后果是业务进程加载错误配置。

另一方面，当前表单允许用户手工输入任意模版名称字符串，输入错别字或填写已不存在的名称同样只能
在执行阶段才被发现。

配置模版的唯一标识（模版 ID）不会被复用，删除后重建必然产生新的 ID。改为按 ID 圈定后，
「原模版已删除」这一事实会在执行时被明确暴露为失败，而不是静默转移到另一个模版上。

### 用户故事

作为在标准运维流程中配置「生成配置 / 下发配置 / 检查配置」节点的用户
我想要从下拉列表中选择配置模版，而不是手工填写模版名称
以便于避免输入错误，也不必关心名称是否被他人改动。

作为流程的执行者
我想要在所选配置模版已被删除时收到明确的失败提示
以便于及时发现流程参数已失效，而不是让任务作用到一个同名的新模版上。

作为负责本次变更上线的运维人员
我想要有一个可控开关，在存量流程完成参数重填之前禁止「不指定配置模版」的操作通过
以便于避免存量流程在升级后误触发对全部配置模版的操作。

作为业务负责人
我想要在确认所有流程都已重填参数后关闭该开关
以便于恢复「不指定配置模版即操作全部配置」这一便利用法。

## 功能需求

### 核心功能点

| 功能编号 | 功能描述 | 优先级 | 涉及角色 | 备注 |
|---------|---------|--------|---------|------|
| F-001 | 配置类操作的模版圈定方式由「模版名称」改为「模版唯一标识（模版 ID）」 | P0 | 流程配置者、流程执行者 | 必须 |
| F-002 | 插件表单的配置模版字段改为「只能从下拉列表选择」，取消手工输入 | P0 | 流程配置者 | 必须 |
| F-003 | 所选模版 ID 不存在（模版已被删除）时执行失败，并列出全部失效的模版 ID | P0 | 流程执行者 | 必须 |
| F-004 | 提供环境级开关，控制「未指定配置模版」是否允许通过，默认不允许 | P0 | 运维人员 | 必须 |
| F-005 | 服务端不再接受按模版名称圈定操作范围 | P0 | — | 必须 |

### 详细功能描述

#### [F-001] 按模版 ID 圈定配置操作范围

- **输入**：流程配置者在插件表单中选择一个或多个配置模版；执行时插件将所选模版的唯一标识
  提交给 bscp。
- **处理逻辑**：
  1. 表单加载时向 bscp 拉取当前业务下的配置模版清单，展示模版名称供用户选择。
  2. 用户选择后，流程模板中保存的是模版 ID，而不是模版名称。
  3. 执行时 bscp 按 ID 和所属业务定位模版，取各模版的最新版本参与生成/下发/检查。
- **输出**：批任务被创建，任务范围仅覆盖所选模版。
- **边界条件**：
  - 模版 ID 归属业务与当前流程业务不一致时，视为不存在。
  - 重复选择同一模版不会导致重复操作。
  - 生效动作仅为生成配置、下发配置、检查配置；进程启停类操作与状态同步操作行为不变。
- **异常处理**：
  - 提交的标识无法识别为合法模版 ID → 执行阶段即失败，不创建任务。

#### [F-002] 配置模版只能从下拉列表选择

- **输入**：流程配置者在插件表单中点击配置模版字段。
- **处理逻辑**：
  1. 字段展示当前业务下的配置模版名称列表，支持搜索与多选。
  2. 取消原有的「允许自行创建选项」能力，用户无法输入列表以外的内容。
  3. 该字段仅在执行命令为生成配置、下发配置、检查配置时可见。
- **输出**：用户选中的模版集合。
- **边界条件**：
  - 模版清单拉取失败或业务下没有模版时，下拉展示为空，不阻塞表单其它字段填写。
- **异常处理**：
  - 清单中存在名称为空或标识异常的数据 → 该项不展示。

#### [F-003] 模版已删除时明确失败

- **输入**：执行一个引用了已删除模版的流程。
- **处理逻辑**：
  1. bscp 按提交的模版 ID 集合定位模版。
  2. 比对提交集合与定位结果，识别出全部无法定位的 ID。
- **输出**：执行失败，错误信息中列出**全部**失效的模版 ID（而非只报第一个），且不创建任何
  批任务、不产生任何下发动作。
- **边界条件**：
  - 部分模版存在、部分已删除时，同样整体失败，不对存在的部分「先干一半」。
- **异常处理**：
  - 错误信息需支持中英文，中文表述需说明是「以下 ID 的配置模版未找到」。

#### [F-004] 配置模版必填校验开关

- **输入**：部署环境的环境变量配置。
- **处理逻辑**：
  1. 开关**默认开启**。未配置、配置为空、配置了无法识别的值时，均按开启处理。
  2. 开关开启时，执行生成配置、下发配置、检查配置且未指定任何配置模版，则执行失败，
     不创建任务。
  3. 开关关闭时，未指定配置模版恢复为「操作当前业务下全部配置模版」。
  4. 进程启停类操作与状态同步操作不受该开关影响。
- **输出**：开关开启且未选模版时的失败提示，需说明是当前环境要求必须选择配置模版，
  而非字段本身异常。
- **边界条件**：
  - 插件表单无法感知环境变量，因此开关开启时表单上该字段**仍显示为非必填**，用户可以保存
    空值，直到执行阶段才失败。这是本期接受的表现，不为此单独改造表单必填标记。
- **异常处理**：
  - 无。开关只影响校验是否生效。

#### [F-005] 服务端停止支持按模版名称圈定

- **输入**：任何调用方提交的操作范围参数。
- **处理逻辑**：
  1. 服务端不再解析操作范围中的模版名称字段，该字段从接口契约中移除。
  2. 移除后保留字段占位，防止后续被复用为其它语义。
- **输出**：仅按模版 ID 或「全部模版」两种方式确定操作范围。
- **边界条件**：
  - 已确认当前仅进程配置管理插件会提交该字段，无其它调用方。
- **异常处理**：
  - 仍提交模版名称的调用方，该字段被忽略，等同于「未指定模版」。

## 非功能需求

### 性能需求

- **模版查询次数**：按 ID 定位 N 个模版时，数据库查询次数为 1 次，不随 N 线性增长
  （当前按名称的实现已是批量查询，按 ID 不得比它更差）。
- **响应时间**：本需求不改变任务创建与轮询的响应时间特征，无新增指标。

### 安全需求

- **权限控制**：沿用现有插件鉴权与用户身份透传机制，本需求不新增权限模型。
- **数据隔离**：按模版 ID 定位模版时必须带业务维度约束，禁止跨业务定位到其它业务的模版。
- **数据保护**：本需求不涉及敏感数据存储或传输方式变更。

### 可用性与稳定性

- **失败方式**：所有异常场景（模版已删除、开关开启但未选模版、标识非法）都必须表现为
  「执行失败且不产生任何下发动作」，禁止出现「部分执行」或「静默扩大操作范围」。
- **容错能力**：模版清单拉取失败时表单降级为空列表，不影响流程其它节点的配置与保存。

### 兼容性

- **接口兼容**：本需求为**破坏性变更**，不保留双写与名称兼容期。
- **存量流程**：存量流程模板中保存的是模版名称，插件升级后该参数失效。在必填校验开关开启的
  情况下，这类流程执行时明确失败，需要使用方重新选择配置模版后才能恢复执行。
- **上线顺序**：插件先上线（开关保持默认开启），服务端后上线。若顺序颠倒，存量流程会在服务端
  上线的瞬间从「按名称操作」变为「操作全部模版」。

## 业务规则

### 业务逻辑规则

- **规则 R-001**：配置操作范围的唯一合法圈定方式是模版 ID；模版名称不再具备圈定语义。
- **规则 R-002**：「未指定配置模版」的语义是「操作当前业务下全部配置模版」，但该语义是否可用
  由必填校验开关决定。
- **规则 R-003**：只要存在任一无法定位的模版 ID，整个操作失败，不做部分执行。
- **规则 R-004**：模版 ID 的定位范围限定在当前流程所属业务内。
- **规则 R-005**：模版圈定只作用于生成配置、下发配置、检查配置三个操作；其余操作不受影响。

### 数据校验规则

- **必填字段**：配置模版字段在必填校验开关开启时必填（执行阶段校验），关闭时非必填。
- **格式要求**：模版标识必须能被识别为正整数；重复项去重；无效的空标识被剔除。
- **取值范围**：模版 ID 取值来自 bscp 返回的当前业务配置模版清单。

### 权限规则

- 沿用现有规则，无变更。流程执行者的身份透传给 bscp 用于鉴权与操作审计。

### 接口契约

操作范围参数中的模版圈定字段变更（示意）：

```diff
 "operate_range": {
   "environment": "环境类型",
   "expression_scope": { "进程筛选表达式各段": "..." },
-  "config_template_names": ["模版名称A", "模版名称B"]
+  "config_template_ids": [模版ID_A, 模版ID_B]
 }
```

表单下拉数据源返回结构变更：选项的显示文案仍为模版名称，选项值由模版名称改为模版 ID。

### 数据模型

不新增、不变更数据实体。任务批次记录中本来就以模版 ID 记录本次任务涉及的模版，无需调整。

### 功能验收

      Then 配置模版字段可见，且下拉能加载出该业务下的模版名称列表。

- [ ] **AC-003**：Given 用户选择了 2 个配置模版并保存流程，When 重新打开该流程节点，
      Then 两个模版仍被正确选中并显示为模版名称。
- [ ] **AC-004**：Given 流程已选定 2 个配置模版，When 执行「生成配置」，
      Then 任务创建成功，且任务范围只包含这 2 个模版对应的配置。
- [ ] **AC-005**：Given 流程选定的模版中有 1 个已被删除，When 执行「下发配置」，
      Then 执行失败，错误信息中包含该失效模版的 ID，且不产生任何配置下发动作。
- [ ] **AC-006**：Given 流程选定的模版中有 2 个已被删除，When 执行「检查配置」，
      Then 错误信息中同时列出这 2 个失效模版的 ID，而不是只列出 1 个。
- [ ] **AC-007**：Given 必填校验开关为默认状态（未配置），When 执行未选择任何配置模版的
      「生成配置」，Then 执行失败，提示当前环境要求必须选择配置模版，且不创建任务。
- [ ] **AC-008**：Given 必填校验开关被显式关闭，When 执行未选择任何配置模版的「生成配置」，
      Then 任务创建成功，范围覆盖当前业务下全部配置模版。
- [ ] **AC-009**：Given 一个仍保存着模版名称的存量流程，When 在插件升级后且开关开启的情况下
      执行，Then 执行失败并给出可读提示，不会对全部配置模版执行操作。
- [ ] **AC-010**：Given 执行命令为「启动」等进程类操作或「同步状态」，When 未选择配置模版，
      Then 不受必填校验开关影响，操作正常执行。
- [ ] **AC-011**：Given 提交的模版 ID 属于另一个业务，When 执行配置操作，
      Then 该 ID 被判定为不存在并按 AC-005 的方式失败。

## 边界范围

### 本期包含

- 配置类操作（生成配置、下发配置、检查配置）的模版圈定方式改为模版 ID。
- 插件表单配置模版字段改为纯下拉选择，取消手工输入。
- 模版 ID 失效时明确失败并列出全部失效 ID。
- 环境级必填校验开关，默认开启。
- 服务端停止支持按模版名称圈定，并从接口契约中移除该字段。

### 本期不包含

- 任务历史 / 任务详情页面将模版 ID 反查回显为模版名称。
- 「下发配置」动作内部同步阻塞轮询的异步化重构。
- 为必填校验开关提供页面级的表单必填标记（表单为静态定义，读不到环境配置）。
- 存量流程参数的自动迁移（不做名称到 ID 的自动换算，由使用方重新选择）。
- 页面路径（非插件路径）的配置操作行为调整。

## 约束条件

- **技术限制**：插件表单为静态定义文件，无法感知部署环境的开关状态，因此必填校验只能在执行
  阶段生效。
- **上线约束**：必须插件先上线、服务端后上线；开关首次上线必须处于开启状态。
- **运营约束**：关闭开关前必须确认所有存量流程已完成参数重填，否则「未指定即全量」的风险回归。
- **资源限制**：无额外人力与环境要求。
