## 需求背景

### 业务背景

标准运维通过两类入口发起进程配置管理的配置类操作（生成、下发、检查）：

- 内置 GSEKit 插件：业务已切换到 bscp 进程配置管理时，请求转发到 bscp；
- 独立标准插件（进程配置管理插件）：直接调用 bscp。

两类入口在配置类动作下都可以不填配置模版 ID，也可以指定一组模版 ID，再用表达式圈定进程范围。

原 GSEKit 的语义是：**只对「范围内进程 × 该进程已绑定模版」执行任务**。不填模版 ID 并不等于操作业务下全部模版；范围内未绑定指定模版的进程会被跳过，不挡住其它进程。

当前 bscp 插件路径的行为与之不一致：

1. **不填模版 ID** 会被解释成「业务下全部配置模版」，再和范围内全部进程做绑定校验。
2. 范围内只要有一个进程没有绑到当前这批模版，**整单失败**，已绑定的进程也无法执行。
3. 独立标准插件还保留了一个「配置模版必填」环境开关：默认开启时，未选模版会在插件侧直接失败。该开关是为了防止「空值 = 业务全量模版」误操作，bscp 后台本身并不校验这个开关。

结果是：已经按 GSEKit 习惯编写的流程（不填模版、或圈定范围里混有未绑定进程）在切到 bscp 后无法跑通；一旦关掉必填开关，空值又会扩大成业务全量模版，存在误生成、误下发风险。

本需求把插件路径的配置类操作对齐原 GSEKit：**按进程已绑定模版执行**；同时下线已无必要的必填开关，并废除「未指定 = 业务全量模版」这一语义。

### 用户故事

作为在标准运维中配置「生成配置 / 下发配置 / 检查配置」节点的流程配置者
我想要不填配置模版时，系统只处理范围内进程已经绑定的模版
以便于沿用原 GSEKit 的用法，不必为了防全量误操作而强制每个节点都选模版。

作为标准运维流程的执行者
我想要范围内即使混有未绑定指定模版的进程，已绑定的进程仍能完成生成 / 下发 / 检查
以便于一次任务不会因为个别未关联进程而整单失败。

作为标准运维流程的执行者
我想要在范围内完全没有可执行绑定时，在任务创建阶段就收到明确失败，且不产生批任务
以便于立刻发现「圈定范围与模版没有交集」，而不是等到批次跑完才知道什么都没做。

作为插件部署运维人员
我想要下线「未选模版即失败」的必填开关
以便于空值不再被拦截，也不再被解释成业务全量模版。

### 详细功能描述

#### [F-001] 未指定模版 ID 时按进程已绑定模版执行

- **输入**：插件发起生成 / 下发 / 检查，操作范围带环境与进程表达式，未指定任何配置模版 ID。
- **处理逻辑**：
  1. 按表达式圈定当前业务、当前环境下的进程。
  2. 对每个命中进程，只取该进程已绑定的配置模版（含绑定到进程实例、以及绑定到该进程所属进程模板的模版，对齐原 GSEKit）。
  3. 仅为上述「进程 × 已绑定模版」创建配置任务，取各模版最新版本。
  4. 业务中存在、但范围内进程都未绑定的模版，不参与本次操作。
- **输出**：批任务仅覆盖实际绑定关系对应的配置；任务详情明细中只有这些将执行的对象。
- **边界条件**：
  - 同一模版绑定到范围内多个进程时，每个进程各自生成/检查一份，不合并成一次。
  - 进程未绑定任何模版时，该进程不进入本次任务（见 F-002 静默跳过）。
- **异常处理**：
  - 表达式未命中任何进程 → 不创建批任务，失败原因说明范围内没有进程（沿用现有语义）。
  - 命中了进程但没有任何已绑定模版 → 走 F-003。

#### [F-002] 指定模版 ID 时按绑定关系过滤，未绑定静默跳过

- **输入**：插件指定了一个或多个配置模版 ID，并带进程表达式范围。
- **处理逻辑**：
  1. 先按模版 ID 定位模版；任一 ID 在当前业务下不存在（含已删除、跨业务）→ 整单失败，列出全部缺失 ID，不创建批任务（沿用「插件模版 ID 替换」）。
  2. 模版均存在时，按表达式圈定进程。
  3. 只保留「该进程已绑定且落在指定 ID 集合内」的模版；未绑定指定模版的进程不创建子任务，也不写入任务详情。
  4. 指定集合里某个模版在范围内没有任何绑定进程时，该模版本轮无任务，不单独报错；只要其它模版仍有可执行对象，任务创建成功。
- **输出**：批任务只包含指定模版与范围内已绑定进程的交集。
- **边界条件**：
  - 重复指定同一模版 ID 不导致重复操作。
  - 进程绑了指定集合之外的其它模版 → 那些模版本次不执行。
- **异常处理**：
  - 指定模版全部存在，但与范围内进程的绑定交集为空 → 走 F-003。

#### [F-003] 零可执行绑定时立即失败

- **输入**：表达式已命中进程，但按 F-001 或 F-002 计算后没有任何「进程 × 已绑定模版」可执行。
- **处理逻辑**：
  1. 不创建批任务，不产生生成、下发、检查动作。
  2. 向调用方返回明确失败，说明范围内没有可执行的配置绑定。
- **输出**：创建接口失败；标准运维节点在发起后即可失败，无需进入批次轮询。
- **边界条件**：
  - 与「表达式未命中进程」区分：前者是没有进程，后者是有进程但没有可执行绑定；失败原因文案不可混用。
- **异常处理**：无额外分支，本条本身即异常路径。

#### [F-004] 生成、下发、检查使用同一套范围语义

- **输入**：插件执行命令为生成配置、下发配置或检查配置。
- **处理逻辑**：
  1. 三类动作确定「本次操作哪些进程、哪些模版」的规则与 F-001 / F-002 / F-003 完全一致。
  2. 下发配置不得在生成结果之外再扩大模版或进程范围；本次未生成的对象不得被下发。
- **输出**：同一操作范围下，生成与检查的作用对象一致；下发对象是本次生成结果的子集或全集，不超出本次绑定过滤结果。
- **边界条件**：进程启停、托管/取消托管、刷新进程状态不受本需求影响。
- **异常处理**：生成阶段已按 F-003 失败时，不得继续发起下发。

#### [F-005] 下线配置模版必填开关

- **输入**：独立标准插件执行配置类动作且未选择配置模版。
- **处理逻辑**：
  1. 不再根据环境变量拦截「未选模版」；未选模版的请求可以发到 bscp。
  2. 后台按 F-001 执行，不再把空值解释成业务全量模版。
  3. 标准运维内置 GSEKit 插件本来就没有该开关，只需享受后台新语义。
- **输出**：未选模版不再出现「当前环境要求必须选择配置模版」类失败。
- **边界条件**：
  - 进程类动作、状态同步动作行为不变。
  - 该开关仅存在于独立标准插件侧，bscp 后台原本没有对应校验，无需删除后台开关配置。
- **异常处理**：无。开关下线后，空值的唯一合法语义是 F-001。

#### [F-006] 更正「不指定即全量」的使用说明

- **输入**：流程配置者查看配置模版字段说明或占位提示。
- **处理逻辑**：凡向使用者表达「不指定配置模版」含义的文案，改为「不指定则按范围内进程已绑定的模版执行」，删除「操作全部配置」及必填开关相关表述。
- **输出**：使用者按文案理解的行为与 F-001 一致。
- **边界条件**：表单字段仍允许为空（非界面必填）。
- **异常处理**：无。

## 非功能需求

### 性能需求

- **任务创建耗时**：在测试环境、同一业务下，范围内约 100 个进程、业务约 20 个配置模版时，对比两种请求——① 不填模版 ID；② 显式指定这些进程全部已绑定的模版 ID——生成配置 / 检查配置的**创建接口** P99 耗时相对差小于 20%。测量方式：同一测试环境连续发起不少于 50 次请求，用接口访问日志中的耗时字段统计 P99。
- **本需求不改变**批次内单个配置生成/下发/检查的执行耗时基线，不新增执行阶段性能指标。

### 安全需求

- **权限控制**：沿用现有插件鉴权与用户身份透传，不新增权限模型。
- **数据隔离**：模版与进程的定位必须带当前业务约束；指定的模版 ID 属于其它业务时视为不存在，整单失败。
- **误操作防护**：空模版 ID 不得再作用到范围内进程未绑定的模版，避免一次任务覆盖业务全量配置。

### 可用性与稳定性

- **失败方式**：
  - 有可执行绑定时：未绑定对象静默跳过，不导致整单失败。
  - 零可执行绑定、无命中进程、指定模版 ID 缺失：创建阶段失败，且不产生任何生成/下发/检查动作。
- **任务详情**：只展示实际执行对象；调用方不能依赖「忽略记录」来发现未绑定进程。未绑定情况若需排查，应通过失败文案（零绑定）或事先核对该进程的模版绑定。

### 兼容性

- **语义为破坏性变更**：插件路径下「未指定模版 ID = 业务全量模版」不再成立；依赖该语义的流程会从「操作全部模版」变为「只操作范围内进程已绑定模版」。
- **必填开关下线为破坏性变更**：独立标准插件上，原先因未选模版而失败的流程会开始执行（按 F-001）。需要在发布说明中告知使用方。
- **调用面**：仅插件 `operate_range` 路径。页面显式指定模版组 + 进程列表的路径行为不变。
- **上线顺序**：后台新语义与插件开关下线应同期生效。若只下线开关、后台仍按全量模版执行，空值会短暂回到「业务全量」高风险行为，不可接受。

## 业务规则

### 业务逻辑规则

- **规则 R-001**：插件路径未指定配置模版 ID 时，操作对象 = 范围内每个进程已绑定的配置模版；不等于业务下全部配置模版。
- **规则 R-002**：插件路径指定了配置模版 ID 时，操作对象 = 指定模版集合与范围内进程已绑定模版的交集。
- **规则 R-003**：未进入交集的进程或模版静默跳过，不写入本次批任务明细，也不因此将整单标为失败。
- **规则 R-004**：交集为空（范围内有进程，但没有任何可执行绑定）时，不创建批任务，创建阶段失败。
- **规则 R-005**：指定的模版 ID 存在缺失时，整单失败并列出全部缺失 ID，即使其余 ID 有效也不部分执行（沿用既有规则）。
- **规则 R-006**：表达式未命中任何进程时，不创建批任务，失败原因与「零可执行绑定」区分（沿用既有规则）。
- **规则 R-007**：独立标准插件不再拦截「配置类动作未选模版」；空值请求必须到达 bscp 并按 R-001 执行。
- **规则 R-008**：R-001～R-004 同时作用于生成配置、下发配置、检查配置；下发范围不得超出本次按绑定关系确定的生成对象。
- **规则 R-009**：进程启停类动作与刷新进程状态不消费模版绑定规则，行为不变。

### Example Mapping

**Story**：作为插件配置类操作的执行者，我希望任务只处理范围内进程已绑定的模版，未绑定的不挡路，完全没有绑定时立刻失败。

| 规则 | 正例 | 反例 |
|------|------|------|
| R-001 | Given 范围内 P1 绑定 T1、P2 绑定 T2，业务另有未绑定到这两进程的 T3，When 不填模版 ID 执行生成，Then 只为 P1-T1、P2-T2 创建任务，T3 不出现 | Given 同上，When 不填模版 ID，Then 为 P1/P2 生成 T3 或把 T3 纳入任务范围 → 不允许 |
| R-002 | Given 指定 T1，P1 绑定 T1，P2 只绑定 T2，When 执行生成，Then 只为 P1-T1 创建任务 | Given 同上，When 执行生成，Then 也为 P2 生成 T1 → 不允许 |
| R-003 | Given 指定 T1，范围内 P1 已绑定、P2 未绑定，When 任务创建成功，Then 任务详情只有 P1，没有 P2 的失败或忽略记录 | Given 同上，When 查看任务详情，Then 出现 P2 的忽略/失败明细 → 本期不这样做 |
| R-004 | Given 范围内进程均未绑定指定模版（或均未绑定任何模版），When 执行生成/下发/检查，Then 不创建批任务，返回「范围内没有可执行的配置绑定」类失败 | Given 同上，When 执行，Then 创建空批次或全部忽略后标成功 → 不允许 |
| R-005 | Given 指定 T1 与已删除的 T99，When 执行检查，Then 失败且错误信息同时包含 T99，不创建批任务 | Given 同上，When 执行，Then 只对 T1 执行并忽略 T99 → 不允许 |
| R-006 | Given 表达式在当前环境未命中任何进程，When 执行生成，Then 失败原因表明没有命中进程，而不是「没有可执行绑定」 | Given 同上，When 执行，Then 降级为操作业务下全部进程 → 不允许 |
| R-007 | Given 独立标准插件未选模版且执行生成，When 发起任务，Then 请求到达 bscp，并按范围内进程已绑定模版执行（若有绑定） | Given 同上，When 发起任务，Then 插件以「必须选择配置模版」失败且不发请求 → 不允许 |
| R-008 | Given 同一操作范围先生成再下发，When 下发执行，Then 下发对象不超过本次生成按绑定过滤后的结果 | Given 生成只覆盖 P1-T1，When 下发，Then 把 T2 或未绑定进程纳入下发 → 不允许 |
| R-009 | Given 执行命令为启动进程且范围内有未绑定配置模版的进程，When 执行，Then 进程操作仍按表达式范围执行，不因未绑定模版而跳过或失败 | Given 同上，When 执行启动，Then 套用配置绑定过滤而漏掉进程 → 不允许 |

### 数据校验规则

- **必填字段**：配置模版 ID 在配置类动作下**非必填**。环境类型、执行命令仍必填（沿用现有）。
- **格式要求**：若填写模版 ID，须能识别为正整数；重复项去重；0 与空项剔除后若集合为空，按「未指定」走 R-001。
- **取值范围**：模版 ID 仅在当前业务内有效。

### 权限规则

- 沿用现有规则。流程执行者身份透传给 bscp，用于鉴权与操作审计。
- 本需求不新增「查看未绑定进程」或「强制对未绑定进程下发」的权限项。

## 外部依赖与集成

### 外部系统集成

| 系统名称 | 交互方式 | 接口说明 | 认证方式 | 文档链接 |
|---------|---------|---------|---------|---------|
| 标准运维（bk-sops）内置 GSEKit 插件 | HTTP | 业务切换到 bscp 后，将生成/下发/检查转发为 bscp 配置接口；空模版 ID 不传模版限定字段 | 网关应用态 + 用户态 | — |
| 独立标准插件（进程配置管理插件） | HTTP | 配置类动作将操作范围（含可选模版 ID）提交给 bscp；本需求下线其必填开关 | 网关应用态 + 用户态 | — |
| bscp 进程配置管理 | HTTP | 按操作范围创建生成/检查批任务；下发基于已生成批次；本需求改变空模版 ID 与未绑定进程的处理 | 网关应用态 + 用户态 | — |

### 接口契约

插件路径配置类请求的操作范围语义（行为契约，字段名示意）：

```text
operate_range.environment            必填，环境类型
operate_range.expression_scope       进程五段表达式
operate_range.config_template_ids    可选
  - 不传或空：范围内进程已绑定的模版（R-001）
  - 非空：指定 ID 与绑定关系的交集（R-002）；存在缺失 ID 则整单失败（R-005）
```

创建结果：

| 条件 | 调用方可见结果 |
|------|----------------|
| 至少 1 个可执行绑定 | 创建成功，返回批任务 ID；明细仅含实际执行对象 |
| 无命中进程 | 创建失败，原因区分「没有进程」 |
| 有进程但零可执行绑定 | 创建失败，原因区分「没有可执行的配置绑定」 |
| 指定模版 ID 缺失 | 创建失败，列出全部缺失 ID |

页面显式模版组路径（直接给出模版、版本、进程列表）不在本契约变更范围内。

### 数据模型

不新增业务实体。「已绑定」沿用现有配置模版与进程实例 / 进程模板的绑定关系。批任务明细只记录实际执行的进程与模版，不为跳过对象新增「忽略」状态。

## 验收标准

### 功能验收

- [ ] **AC-001**：Given 范围内 P1 绑定 T1、P2 绑定 T2，业务另有 T3 未绑定到 P1/P2，When 插件不填模版 ID 执行生成配置，Then 批任务创建成功，任务只包含 P1-T1 与 P2-T2，不包含 T3。
- [ ] **AC-002**：Given 同上绑定关系，When 插件不填模版 ID 执行检查配置，Then 检查对象与 AC-001 相同，仍不包含 T3。
- [ ] **AC-003**：Given 指定模版 ID 为 T1，P1 绑定 T1，P2 只绑定 T2，When 插件执行下发配置，Then 仅为 P1-T1 生成并下发；P2 不出现在任务详情，且不因 P2 未绑定而导致整单失败。
- [ ] **AC-004**：Given 指定 T1 与 T2，范围内只有 P1 绑定 T1、无人绑定 T2，When 插件执行生成配置，Then 任务创建成功且只包含 P1-T1，不因 T2 无绑定进程而失败。
- [ ] **AC-005**：Given 范围内进程均未绑定任何配置模版，When 插件不填模版 ID 执行生成配置，Then 不创建批任务，失败信息表明没有可执行的配置绑定。
- [ ] **AC-006**：Given 指定 T1，范围内进程均未绑定 T1，When 插件执行检查配置，Then 不创建批任务，失败信息表明没有可执行的配置绑定。
- [ ] **AC-007**：Given 表达式在当前环境未命中任何进程，When 插件执行生成配置，Then 不创建批任务，失败信息表明没有命中进程，且与 AC-005/AC-006 的文案可区分。
- [ ] **AC-008**：Given 指定 T1 与已删除的 T99，When 插件执行生成配置，Then 不创建批任务，错误信息包含 T99，即使 T1 仍存在也不部分执行。
- [ ] **AC-009**：Given 独立标准插件未选择配置模版，When 执行生成配置，Then 插件不再返回「必须选择配置模版」类错误；请求到达 bscp 后按 AC-001 或 AC-005 的结果处理。
- [ ] **AC-010**：Given 内置 GSEKit 插件在已切换 bscp 的业务下不填模版 ID，When 执行生成配置，Then 行为与独立标准插件的 F-001 / F-003 一致（按绑定执行或零绑定失败）。
- [ ] **AC-011**：Given 同一操作范围已按绑定关系生成成功，When 插件继续下发，Then 下发对象不超过本次生成结果，未绑定模版不会被补入下发。
- [ ] **AC-012**：Given 执行命令为启动进程，范围内存在未绑定配置模版的进程，When 执行，Then 这些进程仍按表达式范围被操作，不套用配置绑定过滤。
- [ ] **AC-013**：Given 页面以显式模版组 + 进程列表发起生成（非插件操作范围），When 执行，Then 本需求不改变该路径的既有行为。
- [ ] **AC-014**：Given 流程配置者打开独立标准插件的配置模版字段，When 查看说明，Then 文案表达为不指定则按进程已绑定模版执行，不再写操作全部配置。

### 性能验收

- [ ] **AC-P01**：Given 测试环境、范围内约 100 个进程、业务约 20 个配置模版，When 分别用「不填模版 ID」与「显式指定这些进程全部已绑定的模版 ID」各发起不少于 50 次生成配置创建请求，Then 两种请求创建接口耗时的 P99 相对差小于 20%（用接口访问日志耗时字段统计）。

### 安全验收

- [ ] **AC-S01**：Given 指定了属于其它业务的模版 ID，When 插件执行生成配置，Then 按模版不存在整单失败，不创建批任务，且不操作当前业务或其它业务的配置。
- [ ] **AC-S02**：Given 不填模版 ID，When 插件执行生成或下发，Then 范围内进程未绑定的模版不会被生成或下发。
