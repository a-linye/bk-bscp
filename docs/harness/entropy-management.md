# 熵管理（Entropy Management）

> 目标：通过可重复检查控制文档、架构、生成物和依赖的漂移，使问题在合入前暴露。

## 1. 文档园艺

### 1.1 检测矩阵

| 检测项 | 触发时机 | 方式 | 处理 |
|-------|---------|------|------|
| 文档引用路径有效 | 每次文档变更/PR | Harness 文档园艺 | 无效引用在同一变更修复 |
| 目录与架构描述一致 | 顶层模块变化后 | `graphify` + 源码核对 | 更新 Harness 和开发地图 |
| API 文档与 `.proto` 一致 | 协议变更后/CI | 仓库生成命令 + `git diff --exit-code` | 差异阻断合入 |
| 生成代码与生成源一致 | 协议或生成器变更后/CI | `.github/workflows/lint.yml` | 差异阻断合入 |
| 构建文档与 `go.mod`/Makefile 一致 | 工具链变化后 | 文档园艺定向检查 | 更新过时版本与命令 |
| Skill/MCP 与工具清单一致 | Skill 或接入变化后 | 对账 `tool-dependencies.md` | 更新 `tooling.md` |
| 词汇与协议字段一致 | 业务概念变化后 | Reviewer 核对 | 更新 `docs/glossary.md` |

已识别的初始偏差：`docs/overview/source_compile.md` 中 Go/protoc 版本低于当前 `go.mod` 和 Makefile 定义。该文档不属于本次 Harness 生成范围，应作为后续文档债处理。

### 1.2 园艺流程

1. 代码提交或用户触发后运行 Harness 文档园艺。
2. P0（可机械修复、权威源明确）在保护用户改动的前提下修复并验证。
3. P1（需要业务或架构判断）列出证据、影响和方案，由维护者确认。
4. 无法在当前变更解决的偏差进入 TAPD/Issue，记录责任人和清理条件。
5. 修复后重新运行受影响维度，不以“已编辑文件”代替验证。

## 2. 代码与架构熵

| 检测类型 | 工具/证据 | 级别 | 约束 |
|---------|----------|------|------|
| Go 格式与静态问题 | `gofmt`、`.golangci.yml`、CI | 阻断 | 不引入新增错误 |
| 模块依赖漂移 | `go mod tidy` 检查 | 阻断 | `go.mod`/`go.sum` 必须可重现 |
| 生成物漂移 | `make pb api_docs bkapigw_docs normalize_proto_docs` | 阻断 | 生成后工作区无意外差异 |
| 前端类型与构建 | `npm run lint`、`npm run build`（`ui/`） | 阻断 | 涉及前端时执行 |
| 架构边界违规 | 架构规范 + Review；自动规则待建设 | 阻断新增违规 | 历史例外不得扩散 |
| 死代码与复杂度 | golangci-lint、测试与 Review | 警告/阻断 | 按 `.golangci.yml` 阈值处理 |

## 3. 技术债追踪

### 3.1 分类与记录

| 类型 | 识别方式 | 记录位置 | 清理策略 |
|------|---------|---------|---------|
| 过时文档 | 文档园艺、构建事实核对 | TAPD/Issue 或当前 PR | 权威源明确时优先随变更修复 |
| 历史架构耦合 | 依赖分析、Code Review | 设计文档 + TAPD/Issue | 只在相关需求中渐进拆分 |
| 测试缺口 | 行为变更无对应测试、缺陷回归 | TAPD/Issue | 修复缺陷时先补回归测试 |
| 生成链路脆弱 | CI 生成失败或本地不可复现 | TAPD/Issue | 固化版本和命令，保持 CI 对账 |
| TODO/FIXME | 代码扫描与 Review | 有业务影响时转 TAPD/Issue | 禁止无负责人、无条件长期堆积 |
| 依赖风险 | 安全扫描、模块升级 | TAPD/Issue | 按安全级别和兼容成本处理 |

### 3.2 预算

- 默认未关闭技术债上限为 20 条，每个迭代至少处理 1～2 条。<!-- TODO: 待团队确认阈值。 -->
- 新增债务必须在同一 PR/需求中说明原因、影响、责任人和清理条件。
- 安全红线、数据损坏风险、权限绕过和不可恢复迁移不进入普通债务预算，必须阻断交付。

## 4. 度量

| 指标 | 计算方式 | 初始目标 | 超标动作 |
|------|---------|---------|---------|
| Harness 文档一致性率 | 通过检查项 / 总检查项 | ≥ 95% | 触发完整园艺扫描 |
| 生成物一致性 | 生成后无未提交差异 | 100% | 阻断合入 |
| 新增架构违规 | 当前变更新增数 | 0 | 调整设计或明确例外 |
| 缺陷回归测试率 | 有自动回归测试的缺陷修复 / 缺陷修复总数 | 持续提升 | Review 提醒并登记缺口 |
| 技术债净增量 | 新增 - 已清理 | ≤ 0 | 迭代优先安排清理 |

度量结果必须能追溯到检查命令、CI 或单据；无采集机制的指标标记为待建设，不伪造数值。

## 检查清单

- [ ] 代码、协议、生成物和文档变化已同步
- [ ] 当前变更未扩大历史架构例外
- [ ] 技术债包含影响、责任人和清理条件
- [ ] 安全与数据完整性问题未被降级为普通债务
- [ ] 度量结论有可复现证据
- [ ] 文档园艺发现的问题已修复或进入可追踪单据
